# Metabolic Model Python

This project builds a gene-expression-constrained metabolic model using the Human-GEM genome-scale metabolic reconstruction and COBRApy. The workflow filters genes to those present in the model, normalises expression values, and adjusts reaction bounds based on gene expression before running FBA or FVA.

## Project structure

- `model/Human-GEM.mat` — Human-GEM metabolic model in MATLAB format
- `data/normalised_cpm_counts.csv` — normalised gene expression matrix
- `util.py` — helper functions for mapping gene expression to reaction bounds
- `Constrained_FBA.ipynb` — sample-wise constrained flux balance analysis
- `Constrained_FVA.ipynb` — constrained flux variability analysis
- `results/` — output CSV files generated by the notebooks

## Main workflow

1. Load the Human-GEM model.
2. Filter metabolic gene expressions.
3. Normalise expression values using Min-Max scaling.
4. Map gene expression to reaction-level constraints using GPR rules.
5. Update reaction lower and upper bounds using `update_reaction_bounds`.
6. Run either:
   - FBA to estimate fluxes for each sample
   - FVA to estimate minimum and maximum feasible fluxes under a fraction of optimum

## Helper function

The repository includes a custom utility in `util.py`:

- `update_reaction_bounds(default_model, df, gamma=2)`

This function copies the original model, maps expression values to reactions using each reaction's GPR rule, and scales the model bounds according to gene expression.

## Requirements

Install the Python dependencies:

```bash
pip install pandas numpy scikit-learn tqdm cobra
```

A working COBRA solver is also required. In this project the solver is configured as `glpk`, so ensure GLPK is installed and available in your environment.

## Run the analysis

Open the notebooks in Jupyter or VS Code and run the cells in order:

- `Constrained_FBA.ipynb`
- `Constrained_FVA.ipynb`

The notebooks save outputs into:

- `results/FBA_Fluxes.csv`
- `results/maxfluxes.csv`
- `results/minfluxes.csv`

## Notes

- The expression data is expected to have genes as the index and samples/conditions as columns.
- The current implementation uses a simple GPR-to-reaction mapping based on `AND` and `OR` logic.
- Results depend on the model objective and the chosen `gamma` parameter in `update_reaction_bounds`.
